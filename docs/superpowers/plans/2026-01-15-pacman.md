# Pac-Man Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pac-Man classico arcade (labirinto 28×31, 4 fantasmi con AI distinta, power pellets, frutta, progressione livelli) giocabile nel game shell.

**Architecture:** Tre moduli di logica pura — `labirinto.ts` (dati griglia + helper tile), `fantasmi.ts` (AI ghost + state machine), `logica.ts` (stato gioco, tick temporale, collisioni, scoring) — più `pacman.ts` (Gioco: loop `requestAnimationFrame` con delta time, rendering canvas, lifecycle). Registro in `main.ts`.

**Tech Stack:** TypeScript strict (ES2022, ESM, alias `@/`), Vitest 5 + jsdom, Vite 8 (PWA). Niente nuove dipendenze. Audio: WebAudio via `beep()` del core.

**Spec:** `docs/superpowers/specs/2026-01-15-pacman-design.md`

## Global Constraints

- Niente semicoloni; tipi con `import type`; funzioni senza ritorno significativo con `void` esplicito (convenzioni del progetto, AGENTS.md).
- Il gioco non tocca il DOM: solo `ctx.canvas` 2D in unità CSS (DPR già applicato dalla shell). Canvas di prova nei test: `canvas.width = 360; canvas.height = 480`.
- Comandi dichiarati dal gioco: esattamente `['su', 'giu', 'sx', 'dx']`.
- Valori fissati dalla spec: griglia 28×31; velocità base 8 tile/s; pellet = 10 pts; power = 50 pts; ghost = 200×2^n; vite = 3; extra life a 7000; max livello 99.
- Record/punteggio/HUD/overlay/pausa: già della shell — il gioco solo chiama `ctx.invia.punteggio(v)` e `ctx.invia.fine(v)`.
- Beep del gioco: `import { beep } from '@/core/audio'`. Game over: solo i beep della shell.
- Il gioco non modifica file fuori dalla sua cartella + `src/main.ts` (registrazione) + `public/icons/` (icona): zero modifiche a `core/` e `app/`.
- Loop: `requestAnimationFrame` con delta time (non `setInterval` — il gioco è real-time continuo).
- Commit frequenti con messaggio in stile del repo (es. `feat: ...`, `test: ...`).

## Review Focus

Cose che la spec implica ma i test della logica pura non coprono direttamente — i test che le fissano sono aggiunti al task che possiede il codice:

- **Tick mentre la shell è in pausa** (P/Escape o auto-pausa su `visibilitychange`): il gioco non avanza e non finisce — fissato dal test `pausa` di Task 4 (fake timers: `pausa()` poi `advanceTimersByTime(60_000)` → `invia.fine` mai chiamata).
- **Teardown al ritorno al menù** (✕): nessun rAF sopravvive, nessun comando smontato viene eseguito — fissato dal test `smonta` di Task 4 (dopo `smonta()`, `advanceTimersByTime(60_000)` → `fine` mai chiamata; `comanda` dopo `smonta()` è no-op).
- **Delta time elevato** (tab in background, resume con dt > 100ms): il tick non "salta" più di un frame — fissato dal test `dt-cap` di Task 4 (un rAF con dt = 2000ms non causa più di un tick standard).
- **Doppia chiamata `reset()`** (overlay "Rigioca" + tasto R): la partita riparte pulita, un solo loop rAF attivo — fissato dal test `reset` di Task 4.
- **Tunnel wrap-around**: un entity in colonna 27 che va a destra appare in colonna 0 (e viceversa) senza "teleporto" visivo — fissato dal test `tunnel` di Task 3.

- [ ] **Step 3: Implementa `logica.ts`**

Struttura del `tick` (ordine di esecuzione):
1. Se `statoFase !== 'gioco'` → decrementa `timerFase`; a 0: transizione (morte → reset o fine se vite=0; reset → nuovo livello, `statoFase='gioco'`).
2. Avanza Pac-Man: `progresso += velPacman(livello) * dt`. Quando `progresso >= 1` → tile successivo. Se il tile è muro e non c'è `dirPrevista` valida → ferma a `progresso = 1`. Al cambio tile: applica `dirPrevista` se il tile nella nuova direzione è attraversabile; controlla pellet/power/frutta. Wrap tunnel in riga 14.
3. Avanza ogni fantasma: determina velocità (dipende da stato + livello). `progresso += vel * dt`. Quando `progresso >= 1` → tile successivo. Se crossroad → `targetFantasma` + `scegliDirezione`. Wrap tunnel. Gestisce wall-collision (ferma, invert). Stato `casa`: decrementa `timerCasa`, a 0 → `uscita`. Stato `uscita`: muove verso porta, a porta → `attivo`. Stato `occhio`: target = casa, a casa → `casa`.
4. Controlla collisioni Pac-Man/ghost: stessa tile o scambio di tile (pacman va in A e ghost va in B, ghost va in B e pacman va in A). Se ghost `attivo` → morte. Se ghost `spaventato` → mangiato. Se ghost `casa`/`occhio` → nessuna.
5. Aggiorna timer globali: `timerModa` (scatter/chase schedule 8 fasi), `timerSpaventati`, `frutto.timer`. A scadenza `timerModa`: cambia fase, ghost `attivo` invertono direzione. A scadenza `timerSpaventati`: ghost `spaventato` → `attivo`, `catena = 0`.
6. Check vittoria livello: `pelletMangiati === pelletTotali` → `statoFase = 'reset'`, livello++.
7. Check extra vita: `punti >= 7000 && !extraVitaData` → vite+1, `extraVitaData = true`.
8. Check game over: `statoFase === 'morte' && vite === 0` → `statoFase = 'fine'`.

- [ ] **Step 3: Implementa `pacman.ts`**

Struttura:
- `crea(ctx)`: crea stato con `creaStato()`, avvia loop rAF, registra `ctx.comanda`.
- Loop rAF: calcola `dt = (now - last) / 1000`, cap a 0.05s (50ms — evita "jump" al resume). Chiamata `tick()`. Se `statoFase === 'fine'` → `ctx.invia.fine(punti)`, stop loop. Altrimenti `requestAnimationFrame(loop)`.
- Rendering (a ogni frame):
  - Sfondo nero
  - Labirinto: muri come linee blu `#1e3a8a` (2px). Pellet: cerchi piccoli `#fbbf24` (r=2). Power: cerchio grande pulsante (r=5, alpha oscillante).
  - Pac-Man: cerchio giallo `#fbbf24` con arco "bocca" (angolo 0.25-0.75×2π, oscillante). Posizione interpolata tra tile con `progresso`.
  - Fantasmi: corpo semicircolare + onde. Colore per id. Spaventato: `#3b82f6` (flash bianco se `timerSpaventati < 2`). Occhio: solo occhi bianchi.
  - Frutta: emoji-like shape o cerchio colorato a `FRUTTA_POSIZIONE` (se presente).
- Audio:
  - Pellet: `beep(440, 0.05)` + `beep(880, 0.05)` (waka-waka alternato ogni 2 pellet)
  - Power: `beep(220, 0.2)`
  - Ghost mangiato: `beep(400, 0.1)` + `beep(800, 0.1)` + `beep(1200, 0.1)`
  - Morte: `beep(600, 0.2)` + `beep(400, 0.2)` + `beep(200, 0.4)`
  - Frutta: `beep(660, 0.1)` × 3
- Lifecycle: `pausa()` ferma rAF; `riprendi()` riprende; `reset()` nuovo stato + riavvia loop; `smonta()` ferma rAF + cleanup.
- Punteggio: a ogni variazione di `stato.punti` → `ctx.invia.punteggio(stato.punti)`.
